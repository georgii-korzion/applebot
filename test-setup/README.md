# Тестовый сетап

Два этапа: сухой прогон на моке (без Apple, 5 минут) и живые тесты T1–T7 на iPhone 18 Pro 256GB Black (`MJR54AH/A`), который уже продаётся.

**Во всех живых тестах: не платить. После каждого теста — popup → Clean bag в каждом профиле.**

## Что в наборе

**Сама папка `apple-drop-test-setup` — это и есть расширение** (в ней лежит `manifest.json`). В `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» выбирай именно её. Внутри:

| Папка/файл | Зачем |
|---|---|
| `manifest.json`, `*.js`, `*.html`, `icons/` | боевая сборка — это то, что загружает Chrome |
| `extension-dev/` | dev-сборка (умеет работать с моком) — загружать только в отдельный профиль «Mock» |
| `live/*.json` | конфиги живых тестов |
| `mock/config-mock.json`, `mock/run-mock.command`, `mock/mock-server.mjs` | сухой прогон |
| `RESEARCH-iphone18-preorder.md` | как прошёл предзаказ 18 Pro и что учтено |

## 0. Один раз

- Node.js 20+ для мока и хаба: <https://nodejs.org> или `brew install node`.
- Профили Chrome `Drop 1`, `Drop 2`, `Drop 3`, в каждом загружена папка `apple-drop-test-setup` (она же расширение).
- VPN выключен, язык Chrome — English, часовой пояс Mac — Дубай.
- macOS: Системные настройки → Уведомления → Google Chrome — разрешить (иначе не увидишь «Заказ готов к оплате»). Звук идёт из расширения, громкость Mac не на нуле.
- Окна профилей в день дропа не сворачивать (скрытые вкладки Chrome тормозит; расширение от этого защищено, но лишний риск ни к чему). Mac на зарядке, `caffeinate -d` в Терминале.
- Если есть Apple Account: за день до старта в **отдельном** профиле можно нажать «Get Ready» на apple.com/ae — сохранённая конфигурация с оплатой, ручной параллельный путь. Расширению он не мешает (у него гостевой чекаут).

## 1. Сухой прогон на моке

1. Отдельный профиль Chrome «Mock» → загрузить папку `apple-drop-test-setup/extension-dev`.
2. Терминал: `cd <папка набора>/mock && ./run-mock.command` (продажи на моке «откроются» через 60 с; `OPEN_AFTER=120 ./run-mock.command` — через 120 с).
3. В профиле «Mock»: иконка расширения → **Настройки** → **Импорт JSON** → `mock/config-mock.json` → **Проверить и сохранить**.
4. Popup → **Start**. Откроется окно с 2 вкладками на странице iPhone Duo.
5. Что увидишь: до открытия вкладки обновляются; после открытия одна вкладка переживёт заглушку «Almost there», положит товар, пройдёт корзину → Guest → самовывоз (Dubai Mall без наличия → Mall of the Emirates, первое окно «занято» → следующее) → контакты → остановится на «How do you want to pay?». Окно выйдет вперёд со звуком, фокус — в поле карты. Вторая вкладка — `STOPPED`.
6. По желанию: ввести тестовую карту `4111111111111111` → Review Your Order → Place Order. Расширение поймает номер `W…` (popup, уведомление).

Повтор: popup → Stop, в Терминале Ctrl+C и снова `./run-mock.command`, затем Start.

**Прогон «магазин закрыт перед дропом»:** `STORE_CLOSED=blank ./run-mock.command` — до «открытия» все страницы магазина пустые (другие варианты: `backsoon` — «We’ll be back», `redirect` — редирект на заглушку). Импорт того же `config-mock.json` → Start. Что увидишь: вкладки в состоянии `CLOSED`, уведомление «Apple Store закрыт», вкладка обновляется сама (в этом конфиге старт уже «прошёл», поэтому раз в ~1,5 с); через 60 с мок «открывается» → уведомление «Apple Store открылся» → Add to Bag → чекаут → оплата.
Чтобы увидеть и редкий рефреш до старта: в Настройках поставь `openAt` на ~3 минуты вперёд (например `2026-10-01T15:33:00+04:00`) и запусти `STORE_CLOSED=blank OPEN_AFTER=180 ./run-mock.command` — первые 2 минуты обновление раз в ~30 с, последняя минута — раз в ~3 с.

## 2. Живые тесты

В каждом профиле: **Настройки → Импорт JSON → нужный файл из `live/` → вписать Имя, Фамилию, Email, Мобильный (`05XXXXXXXX`); для оплаты картой ещё «Плательщик: улица, Area, город» (Billing Address — Apple требует его) → Проверить и сохранить.** Если сверху красная ошибка — конфиг **не сохранён**, поправь поле и нажми снова (30.09: карта с опечаткой в контрольной цифре → настройки не сохранились → на Billing карта не заполнилась). Получатель — реальный человек, для тестов — свои данные. Жёлтое предупреждение «openAt в прошлом» — так и нужно: товар уже продаётся, старт идёт сразу.

### Что видно в логе в плохих случаях

- `CLOSED` — магазин закрыт / пустая страница, вкладка обновляется по расписанию.
- `QUEUE` — страница очереди Apple, расширение её не трогает до 90 с.
- `… — повтор того же окна` / `Continue to Payment: … — повтор` — ошибка общего вида на чекауте, повтор.
- `корзина пуста после Add to Bag (N)` — сломанная сессия корзины; после 3 раз `STUCK`.
- На оплате: если после Place Order ошибка — **сначала почта и номер заказа, потом повтор** (12.09 у людей вышли дубли).
- `поля карты появились через N с` — норма, блок карты у Apple медленный; `поля карты не появились за 10 с — переключаюсь на Apple Pay` — сработал фолбэк карты (если Apple Pay не нужен — в настройках «Фолбэк карты: нет» и/или увеличить `timing.cardWaitMs`).
- `Review не открылся: Please complete this mandatory field` — на Billing пустые обязательные поля (обычно Billing Address); в логе выше смотри «адрес плательщика: … не удалось: …» или «карта в конфиге не задана».
- `Please read and accept the terms & conditions` — галочка условий на Review не встала (расширение ставит её само и при Apple Pay повторяет клик один раз); поставь руками и пришли лог.

- popup → **Clean bag** в каждом профиле, где была корзина;

## Где лежат данные заказов

После каждого «на оплате» и «оформлен» расширение пишет запись: ФИО, email, телефон, товар, магазин, окно, сумма, способ оплаты, времена (OPEN, на оплате, оформлен), номер заказа. Без масок — это твои данные на твоей машине. Смотреть: popup → раздел «Заказы»; выгрузить: popup → «Экспорт заказов (CSV)» (открывается в Numbers/Excel). С хабом — общая таблица по всем профилям на дашборде и `http://127.0.0.1:8765/api/orders.csv`.

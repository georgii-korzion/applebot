# Apple Drop Bot — флот браузеров для дропа iPhone Duo (apple.com/ae, 16.10.2026 16:00 Дубай)

ТЗ — [docs/BOT-SPEC.md](../docs/BOT-SPEC.md). Сайт Apple по шагам — [docs/HANDOFF.md](../docs/HANDOFF.md).

Бот — надстройка над расширением «Apple Drop Assistant»: со страницей Apple по-прежнему работает расширение, а оркестратор (Node.js) запускает много окон Chrome, раздаёт им заказы, карты и прокси, показывает статус всех браузеров, пишет заказы в файл (и по желанию шлёт в Telegram и на вебхуки) и выводит вперёд окно, которому нужен человек.

**Что делает человек:** подтверждает оплату картой в приложении банка (3-D Secure) и сканирует QR Apple Pay телефоном. Всё остальное, включая Place Order по карте (один клик), — бот. Если что-то застряло, окно этого браузера выходит вперёд со звуком; поправь руками и нажми на плашке **«Продолжить автоматику»**.

---

## 0. Пульт — всё в одном окне

Заполнять JSON руками не нужно: у бота есть **пульт** — страница в браузере, где вводятся заказы, получатели, карты, прокси и время старта, и есть кнопки «Проверить», «Подготовить профили», «▶ Запустить», «■ Остановить всё».

- **На Mac:** двойной клик по файлу **`Apple Drop Bot.command`** в папке бота. Он сам поставит зависимости, соберёт расширение и откроет пульт. Если macOS пишет «не удалось проверить разработчика» — правый клик по файлу → «Открыть» → «Открыть» (один раз).
- **Или в Терминале:** `npm run bot -- ui`.

Пульт работает только на этом компьютере (адрес `127.0.0.1`, ссылка с токеном). Поля проверяются сразу: телефон `05XXXXXXXX`, номер карты по Луну, срок, CVV, адрес прокси; вверху — сколько ошибок и на какой вкладке. «Сохранить» (или ⌘S) пишет `bot.config.json` и `secrets.local.json` (права 600) в корень папки. Окно Терминала с пультом не закрывай, пока работаешь; запущенный бот без пульта продолжит работать.

Вкладки: **Запуск** (имя машины, время старта, готовность машины, пробный/боевой режим, запуск, вывод) · **Заказы** · **Получатели** · **Карты** · **Прокси** · **Браузеры** · **Оплата** · **Уведомления** · **Дополнительно** (сторож, замер скорости, технические порты) · **Результаты** (файл заказов, отчёт).

Ниже — то же самое командами в Терминале.

## 1. Один раз на каждом Mac

Нужен Node.js 20+ ([nodejs.org](https://nodejs.org), LTS). Код — ветка `claude/funny-babbage-0b81ix`:

```bash
git clone -b claude/funny-babbage-0b81ix https://github.com/georgii-korzion/applebot.git
cd applebot
```

Дальше — двойной клик по `Apple Drop Bot.command` (пульт: на вкладке «Запуск» кнопки «Собрать» и «Установить» для Chrome), или вручную:

```bash
npm i
npm run build                         # расширение → dist/
npm run bot -- install-chrome         # Chrome for Testing в runtime/chrome (curl с докачкой: обрыв/зависание — продолжит с места)
cp bot/bot.config.example.jsonc bot.config.json
cp bot/secrets.example.jsonc secrets.local.json && chmod 600 secrets.local.json
```

- **Chrome for Testing обязателен:** обычный Google Chrome с версии ~137 не загружает расширения из командной строки. Бот сам найдёт его в `runtime/chrome`. Обычный Chrome при этом остаётся твоим браузером, бот его не трогает.
- **Несколько Mac работают независимо.** У каждого свой `bot.config.json` (поле `machine` — имя машины), свои заказы, получатели и карты. Одну карту на двух Mac не ставь: лимит `maxOrders` и «одно подтверждение в банке на карту» считаются внутри одного Mac.
- **Сколько браузеров.** Около 0,5 ГБ памяти на браузер плюс нагрузка на процессор в момент дропа. На 16 ГБ начинай с 10–12, на 32 ГБ можно 20 — но только после замера `npm run bot -- bench` (§20, T17): размер флота — наибольший, при котором шаг медленнее одного браузера не больше чем на 20 %.
- `secrets.local.json`: получатели (реальные люди с документом), карты с billing-адресом, прокси, Telegram (необязательно).
- macOS: Системные настройки → Конфиденциальность → **Автоматизация** — разрешить Терминалу управлять «System Events» (вывод окна вперёд). Для запасного клика по Apple Pay средствами macOS (`applePay.osClick`) ещё **Универсальный доступ**. Часовой пояс — **Дубай**.

Проверка машины:

```bash
npm run bot -- check          # в пульте: «Проверить»
```

Проверяет Chrome и загрузку расширения, память, часовой пояс (нужен Asia/Dubai), язык, `caffeinate`, порт хаба, каждый прокси (выходной IP, страна AE, уникальность IP, скорость apple.com/ae, страница товара), конфиг и секреты (телефон `05XXXXXXXX`, карты по Луну, billing-адрес, хватает ли карт и прокси), Telegram — тестовым сообщением.

## 3. День дропа

```bash
caffeinate -d                 # в отдельном окне Терминала (запуск из пульта делает это сам)
npm run bot -- start          # в пульте: «▶ Запустить»; браузеры с разносом 1,5 с, дашборд откроется сам
```

- **Дашборд** `http://127.0.0.1:8765/?token=…` (ссылка печатается при старте): состояние каждого браузера, заказы с контактами получателей, карты, очередь «нужен человек», кнопки: показать окно, продолжить, → Apple Pay, сменить карту, перезапуск, стоп, **«Стоп всех»** (останавливает всё ≤ 1 с), **«Дальше»** (следующее окно).
- **Заказы** — `runtime/orders.txt` (номер, товар, магазин, окно, получатель полностью, карта ****1234) и CSV на дашборде. Все уведомления — `runtime/notify.txt`.
- **Ctrl+C** в оркестраторе браузеры не закрывает: кто получил заказ, доведёт его сам. Запусти `npm run bot -- start` снова — он подхватит живые браузеры и восстановит состояние.
- `npm run bot -- status` — таблица браузеров; `npm run bot -- stop` — закрыть всё.

### Когда нужен человек

Окно выходит вперёд по одному (очередь внимания): 3-D Secure с вводом на странице → QR Apple Pay → проблема на оплате → капча → клик (ассистент) → остальное. На плашке в окне:

- **Продолжить автоматику** — поправил, бот идёт дальше с текущего шага;
- **Дальше я сам** — бот перестаёт действовать в этой вкладке, но ловит номер заказа;
- **Стоп** — браузер выходит из гонки, заказ уходит другому (если Place Order ещё не нажат).

### Оплата

- **Карта:** бот заполняет карту и billing-адрес, ставит галочку условий и нажимает Place Order **один раз**. По одной карте одновременно висит только одно подтверждение в банке (разные карты — параллельно). Подтверди в приложении банка. Ошибка после Place Order — бот повторно не жмёт: сначала почта и номер заказа (12.09 были дубли).
- **Отказ карты:** карта сгорает, этот браузер переходит на Apple Pay (вторая и последняя автоматическая попытка), у всех остальных браузеров эта карта меняется на запасную (`role: reserve`); запасных нет — на Apple Pay.
- **Apple Pay:** QR показывается по одному окну за раз (он живёт недолго и меняется). Бот жмёт «Continue with Pay» сам; если Chrome не открыл QR от программного клика — настоящий клик через CDP, затем (по флагу) клик macOS, затем подсветка — жмёшь ты. Окно с QR — на весь экран; QR закрылся без заказа — бот откроет его снова (до 3 раз).

### Стратегии ожидания (гипотеза 1) и прокси (гипотеза 2)

Как выглядит заглушка Apple в день дропа, заранее неизвестно, поэтому половина флота **перезагружает** её (`refresh`), половина **ждёт**, пока она пустит сама (`hold`, с T−120 с до T+`holdMaxWaitSec`). Через 45 с после первого пропуска хаб сравнивает: одна стратегия пустила ≥2, другая — ни одного → половину отстающих переводит, ещё через 30 с — остальных, кроме двух контрольных. Ручная команда `/strategy all refresh|hold` (или дашборд) выключает автоматику.

Прокси: нужны **статические** резидентские или мобильные адреса ОАЭ (не rotating — IP не должен меняться от запуска до номера заказа); HTTP или SOCKS5 с логином. Chrome ходит в локальный форвардер без пароля, форвардер — в прокси с паролем. `mixed`: часть браузеров идёт с домашнего IP. Заблокированный браузер без заказа перезапускается новым профилем на запасном прокси (прокси сверх `browsers − directBrowsers`); браузер с заказом IP не меняет — к человеку. Оплата с адреса прокси может чаще отклоняться банком — проверь тестом T14.

### После дропа

```bash
npm run bot -- report         # какая стратегия сработала (стратегия × прокси → через N с), заглушки, блокировки по IP
npm run bot -- wipe           # удалить secrets.local.json, профили и runtime/ (кроме report.md, orders.txt, orders.csv)
```

### Старт по стоку (ресток) — без времени дропа

Пульт → «Запуск» → **«Когда начинать»: «Как только появится сток»** (в конфиге `"start": {"mode": "stock", "stockPollSec": 5}`).

- Браузеры открывают страницы товаров и ждут, ничего не кладя в корзину. Наблюдатели (2 браузера на разных IP) раз в ~5 с проверяют самовывоз во всех магазинах всех заказов (тот же JSON `fulfillment-messages`, что видит сайт).
- Появился самовывоз модели заказа в его магазине — сразу гонка: заказ отдаётся только тем браузерам и только на те заказы, где есть сток; модель и магазин со стоком идут первыми.
- Сток кончился, пока шли к чекауту (на выборе магазина «нет в наличии»), — все, кто ещё не на оплате, сами возвращаются в ожидание и ловят следующий. Пауза перед новым сигналом растёт: 10, 20, 40… до 120 с (JSON Apple бывает на шаг позади).
- Время дропа в этом режиме не используется; стратегия ожидания — только refresh.

В режиме «Во время дропа» бот тоже стартует сам, как только Apple откроет продажи (товар станет доступен к покупке) — openAt нужен только для частоты рефреша до старта.

### Если бот повёл себя странно — «Собрать логи»

Пульт → «Запуск» (или «Результаты») → **«Собрать логи»**: на рабочем столе появится `applebot-logs-<машина>-<время>.zip` (логи каждого браузера, хаба, снимки страниц-заглушек и 404). Номера карт, имена, телефоны и почты получателей, пароли прокси и токены в архиве замаскированы; `secrets.local.json` и файла заказов в нём нет. Перетащи архив в чат разработчику. В Терминале: `npm run bot -- diag`.

### Сторож лечит зависания до корзины сам

Если браузер завис до корзины — подготовка опций (ATB_PREP, 75 с), ожидание ответа после Add to Bag (ATB_PENDING, 20 с), STUCK после повторяющихся 404 — сторож сам открывает страницу товара заново и сбрасывает счётчики неудач (до 3 раз, в логе «открываю страницу товара заново (1/3)»). Только потом зовёт человека. В чекауте (после корзины) зависание сразу к человеку — там рисковать нельзя.

### Если браузеры открылись и стоят

На дашборде у всех браузеров `STARTING` и красный кружок — значит расширение в окнах не подключилось к боту. Через 25 с бот сам пишет причину в лог (пульт → «Лог бота»), в колонку «ошибка» на дашборде и в `runtime/notify.txt`. Частые причины:

- **Запущен обычный Google Chrome, а не Chrome for Testing.** Обычный Chrome с версии 137 молча игнорирует расширения из командной строки — сайт в окнах работает, а бот их не видит. Первая строка лога при запуске говорит, какой Chrome запущен (`Apple Drop Bot <версия> · Chrome for Testing …`). `Apple Drop Bot.command` сам ставит Chrome for Testing, если его нет; в пульте строка «Chrome for Testing» должна быть ✓. Бот с обычным Chrome не запускается.
- **Окна прошлого запуска.** Без галочки «начать заново» бот подхватывает уже открытые окна. Если они были открыты не тем Chrome, бот скажет об этом через 25 с — «■ Остановить всё», потом «▶ Запустить».
- **Код обновлён, а пульт старый.** После `git pull` закрой окно Терминала с пультом и снова дважды кликни `Apple Drop Bot.command`. Версия (коммит) видна в шапке пульта; если код в папке новее — пульт показывает красную плашку и не запускает бота.
- **Расширение не собрано или собрано с ошибкой** — пульт → «Пересобрать»; в окне браузера `chrome://extensions` покажет ошибку.
- Подробности: `runtime/logs/b01.chrome.log` (вывод Chrome) и `runtime/orchestrator.log`.

## 4. Telegram (необязательно)

`notify.telegram.enabled: true` и в секретах `botToken`, `chatId`, `allowedUserIds`. Одно закреплённое сообщение со статусом (правка не чаще раза в 3 с), события §12, кнопки на «нужен человек». Команды (только от `allowedUserIds`): `/status`, `/show b07`, `/next`, `/stop b07|all`, `/resume b07`, `/applepay b07`, `/card unburn c1`, `/card b07 c3`, `/strategy all refresh|hold`. **Сообщения с контактами получателей проходят через серверы Telegram — чат должен быть закрытым.**

Вебхуки: `POST` JSON, заголовок `X-Signature: sha256=<HMAC тела с secret>`, три повтора (1, 3, 10 с). В `order.placed` — полные имя, телефон, email; карта всегда только `****1234`.

## 5. Скорость

```bash
npm run bot -- bench --runs 5 --browsers 1,10,20
```

N прогонов до Review (`stopBeforePay`) на товаре, который уже продаётся; таблица по шагам: медиана, худший, разбивка «сеть / ожидание элемента / пауза / прочее» и сравнение с одним браузером. Цель: медиана OPEN → Review ≤ 15 с на одном браузере. Оптимизации за флагами (`directAtb`, `blockHeavy`) включать только после замера «до и после».

## 6. Устройство

```
bot/src/
  main.ts            CLI: ui | check | prepare | start | status | stop | report | bench | wipe | install-chrome
  ui/server.ts       пульт: форма ↔ bot.config.json / secrets.local.json, проверки, запуск команд; ui/page.html — страница
  orchestrator.ts    сборка: хаб + лаунчер + форвардеры + уведомления; подхват живых браузеров после перезапуска
  launcher.ts        процессы Chrome (detached): копия расширения + bootstrap.json, плитка окон, надзор, перезапуск
  chrome.ts, cdp.ts  поиск Chrome, аргументы; минимальный CDP (клик, скриншот)
  hub/server.ts      протокол с расширениями, назначение заказов, ворота Place Order, человек, сторож, H1, дашборд, API
  hub/cards.ts       пул карт;  hub/attention.ts — очередь внимания;  hub/policy.ts — назначение, сторож, адаптация
  proxy/forwarder.ts локальный форвардер (HTTP CONNECT / SOCKS5 с логином), проба живости
  notify/            Telegram, вебхуки, шаблоны, файлы
  check.ts, report.ts, bench.ts, store.ts (runtime/state.json, events.ndjson), os.ts (macOS: окно вперёд, клик, звук)
```

Расширение в режиме бота: файл `bootstrap.json` рядом с `manifest.json` (кладёт лаунчер) → конфиг от хаба в `chrome.storage.session` (карта в памяти, пропадает с закрытием браузера), пульс `STATE` раз в 2 с, `ADMITTED → ASSIGN | SPARE`. Без `bootstrap.json` расширение работает как раньше (автономный режим, `hub/server.mjs` — хаб автономного режима).

Протокол хаба (§13): к старому `REGISTER / WATCHER / OPEN / WIN_REQ / WIN / LOSE / PAY_READY / CLEAN / FAILED / PAY_TURN / ORDERED` добавлены `CONFIG, STATE, SNAPSHOT, ADMITTED, ASSIGN / SPARE / UNASSIGN / RELEASED, SET_STRATEGY, PLACE_REQ / PLACE_TURN, PLACED, PAY_WAIT, CARD_DECLINED, CARD_SWAP / CARD_SWAP_ACK, CARD_REQ, SWITCH_PAY, NEED_HUMAN / HUMAN / HUMAN_DONE, CLICK_REQ / CLICK_DONE, BLOCKED, COMMAND, REJECT`. Хаб слушает только 127.0.0.1, принимает `Origin: chrome-extension://…` и токен браузера из `bootstrap.json`; дашборд — только с токеном.

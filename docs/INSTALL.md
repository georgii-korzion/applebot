# Установка и работа на дропе: пошагово, трудозатраты, сколько нужно людей

> **Старая схема (до FLEET-SPEC, 09–11.10).** Здесь хаб стоит на каждой машине, а данные заказа импортируются в каждый
> профиль руками. Актуальная раскатка — один хаб в интернете, `fleet.json` на всех, клоны одного шаблона:
> `docs/FLEET-RUNBOOK.md` (как), `docs/FLEET-PLAN-50.md` (сколько времени и людей). Этот документ оставлен для сравнения
> и для ручной установки одного-двух профилей без хаба (§3).

Документ для планирования: что делать руками при установке, что расширение делает само, где на дропе нужен человек и сколько людей нужно на 4 сервера. Все времена — оценки по тестам и живым прогонам на iPhone 18 Pro; поведение сайта Apple под нагрузкой 16.10 заранее не известно.

## 0. Коротко

| Что | Оценка |
|---|---|
| Подготовка данных (получатели, карты, JSON) на 12 профилей | 1–1,5 ч, один человек |
| Установка одного сервера с нуля (3 профиля) | 50–70 мин |
| Установка 4 серверов | 3,5–4,5 ч одним человеком или ~1 ч вчетвером параллельно |
| Живые тесты (один раз, на одном сервере) | 1,5–2 ч |
| Обновление расширения на новую версию | ~5 мин на сервер |
| Проверка накануне | 10–15 мин на сервер |
| В день дропа до старта | ~15 мин на сервер, начать за час |
| Ручная работа на один заказ во время дропа | 20–60 с (подтверждение оплаты) + редкие вмешательства |
| Людей на 4 сервера | **2 оператора**, если на сервер 1–2 заказа; **4 оператора**, если 3–4 заказа на сервер. Плюс люди с телефонами для подтверждения оплаты — см. §10 |

Ключевое: почти весь путь от ожидания старта до экрана оплаты идёт сам. Человек нужен в трёх местах: нажать Start, подтвердить оплату на телефоне и разобрать редкие сбои, о которых расширение сообщает звуком и уведомлением.

## 1. Что такое «сервер» в этой схеме и что ему нужно

Сервер — это компьютер с рабочим столом, на котором открыт Chrome. Расширение работает внутри обычного Chrome, поэтому без экрана (headless) оно не годится: в некоторых местах нужен человек, и он должен видеть окно.

| Требование | Почему |
|---|---|
| Mac или Windows с рабочим столом (Linux тоже, но не проверяли) | Chrome с расширением, видимое окно |
| Google Chrome 120+ | расширение под Chrome |
| Интернет с IP в ОАЭ, без VPN и прокси | иначе Apple показывает выбор страны или ведёт себя иначе; серверы в дата-центре Apple может встретить хуже, чем домашний интернет — расширение это не обходит и обходить не должно |
| Точное время (синхронизация включена) | фазы рефреша считаются от 16:00 по часам компьютера |
| Компьютер не засыпает, экран не блокируется | спящий Chrome ничего не жмёт |
| Окно Chrome не свёрнуто; удалённая сессия (RDP/VNC/AnyDesk) не отключена | Chrome резко тормозит скрытые и свёрнутые окна |
| Звук и уведомления Chrome включены | так расширение зовёт человека |
| Node.js 20+ | только если нужен хаб (§3.7) |

Сколько ставить на сервер:
- **3 профиля Chrome** на сервер — разумный максимум для одного человека у экрана; до 4 — если сервер мощный.
- **2–3 вкладки** в профиле; всего на сервере до 12 вкладок.
- **Один профиль = одна корзина = один заказ одновременно.**
- **Один заказ живёт только на одном сервере.** Если один и тот же заказ запустить на двух серверах, они не узнают друг о друге и оба дойдут до оплаты (дубль).

Две схемы использования профилей на сервере:

| Схема | Что | Хаб на сервере |
|---|---|---|
| А. Гонка за одним заказом | 3 профиля ведут **один** заказ; кто первый положил в корзину — оформляет, остальные в запасе и чистят корзины | **обязателен**, иначе все три дойдут до оплаты |
| Б. Каждый профиль — свой заказ | 3 профиля, 3 разных получателя | желателен: общий сигнал старта и очередь оплаты по одному окну |

## 2. Что подготовить заранее (не на сервере)

1. **Таблица распределения** — одна строка на профиль:

   | Сервер | Профиль | profileId | Заказ | Модель | Магазины | Получатель (ФИО как в документе) | Email | Телефон 05… | Оплата | Плательщик (чей телефон) | Оператор |
   |---|---|---|---|---|---|---|---|---|---|---|---|

2. **Получатели.** Apple выдаёт заказ при самовывозе по документу на имя получателя. Нужны реальные люди, которые придут в магазин.
3. **Оплата.** Для каждого заказа решить:
   - Apple Pay — подтверждает владелец iPhone, сканируя код с экрана сервера;
   - карта — банк присылает подтверждение в приложение владельцу карты; если включено «Нажимать Place Order самим», больше ничего делать не нужно.
4. **JSON-файлы.** Взять шаблон из `live/` архива, вписать модель (`targets`), магазины, `openAt` = `2026-10-16T16:00:00+04:00`, получателя, при карте — карту и адрес плательщика. На профиль — свой файл (или один на заказ для схемы А).
5. **Хранение JSON.** Файлы с картами не пересылать через мессенджеры и почту. Переносить на сервер напрямую (флешка, AirDrop, общий диск только у вас), после импорта удалить.

Время: ~5 минут на профиль, если данные под рукой → 12 профилей ≈ 1 ч.

## 3. Установка одного сервера, по кнопкам

### 3.1 Подготовка системы (один раз, 15–20 мин)

**Mac:**
1. Системные настройки → Основные → Дата и время → «Устанавливать автоматически» вкл., часовой пояс — Дубай.
2. Системные настройки → Уведомления → Google Chrome → разрешить, стиль «Предупреждения».
3. Системные настройки → Экран блокировки / Аккумулятор → не выключать дисплей, не засыпать (на зарядке).
4. Громкость не на нуле.
5. Установить Google Chrome; язык Chrome — English (Настройки → Языки).
6. VPN выключить.

**Windows:**
1. Параметры → Время и язык → «Установить время автоматически» вкл., часовой пояс (UTC+04:00) Абу-Даби, Маскат.
2. Параметры → Система → Уведомления → Google Chrome → вкл.
3. Параметры → Система → Питание → «Никогда» для отключения экрана и сна.
4. Звук не на нуле (через удалённый рабочий стол — включить передачу звука в клиенте).
5. Google Chrome, язык English. VPN выключить.

### 3.2 Node.js (только для хаба, 5 мин)

Скачать LTS с <https://nodejs.org>, установить с настройками по умолчанию. Проверить: Терминал (Mac) или «Командная строка» (Windows) → `node -v` → должно быть `v20…` или выше.

### 3.3 Архив (2 мин)

Скопировать `apple-drop-test-setup.zip` на сервер, распаковать в постоянное место (например, Документы). Получится папка `apple-drop-test-setup`. Её не переносить и не переименовывать после установки — Chrome грузит расширение прямо из неё.

### 3.4 Профили Chrome (5 мин)

Chrome → значок профиля справа сверху → «Добавить» → «Продолжить без аккаунта» → имя `Drop 1`. Повторить для `Drop 2`, `Drop 3`. У каждого профиля своё окно Chrome.

Быстро открыть все профили:
- Mac: `scripts/open-profiles.command 3` из исходников или вручную через значок профиля;
- Windows: ярлык с `chrome.exe --profile-directory="Profile 1"` (имя папки профиля — `chrome://version` → «Путь к профилю», последняя часть).

### 3.5 Расширение в каждом профиле (1–2 мин на профиль)

В окне профиля:
1. Адресная строка → `chrome://extensions` → Enter.
2. Справа сверху включить **«Режим разработчика»**.
3. **«Загрузить распакованное»** → выбрать папку **`apple-drop-test-setup`** (ту, где лежит `manifest.json`; не выше, не `extension-dev`) → «Выбрать».
4. Значок пазла в панели Chrome → закрепить «Apple Drop Assistant».
5. Откроется страница настроек.

### 3.6 Настройки в каждом профиле (3–5 мин на профиль)

На странице настроек:
1. **«Импорт JSON»** → выбрать файл этого профиля.
2. Поле **profileId** — вписать вручную (`drop-1`, `drop-2`…; импорт его не меняет).
3. Поле **Хаб** — `ws://127.0.0.1:8765`, если на сервере будет хаб; иначе пусто.
4. Проверить глазами: модель, магазины, город, получатель, телефон `05XXXXXXXX`, способ оплаты, карта, адрес плательщика.
5. **«Проверить и сохранить»**. Сверху должно появиться «Сохранено». Если красный блок «Не сохранено» — поправить перечисленное и нажать снова (настройки с ошибкой не сохраняются; например, опечатка в номере карты).
6. Жёлтые предупреждения — прочитать: карта хранится в профиле открытым текстом; при «Place Order самим» заказ может оформиться без человека, если банк не спросит подтверждение.
7. Удалить JSON-файл с карты/диска сервера после импорта.

### 3.7 Хаб (3 мин, если нужен)

1. В папке `apple-drop-test-setup/hub` двойной клик **`run-hub.command`** (Mac) или **`run-hub.bat`** (Windows).
2. Откроется окно с текстом «хаб слушает ws://127.0.0.1:8765». **Окно не закрывать** до конца дропа.
3. В браузере `http://127.0.0.1:8765` — дашборд: профили онлайн, кто ведёт заказ, очередь оплаты.
4. В popup каждого профиля значок **«hub ●»** зелёный.

Хаб слушает только этот компьютер. На каждом сервере — свой хаб.

### 3.8 Prepare в каждом профиле (1 мин на профиль)

Значок расширения → **Prepare**. Само: откроет apple.com/ae, проверит, что нет выбора страны, очистит корзину, откроет страницу товара. В popup появится «Prepare ✓ …». Если «✗» — читать причину (обычно VPN или магазин уже закрыт; во втором случае Start всё равно можно жать).

### 3.9 Быстрая проверка (5–10 мин, один профиль на сервер)

На уже продающемся iPhone 18 Pro: импортировать `live/T1-T3-single.json` с данными получателя → Start → расширение должно дойти до «How do you want to pay?». **Не платить.** Popup → Stop → Clean bag. Потом снова импортировать боевой JSON.

### 3.10 Сводка по времени на сервер

| Шаг | Время |
|---|---|
| Система, Chrome, уведомления, сон, время | 15–20 мин |
| Node.js | 5 мин |
| Архив | 2 мин |
| 3 профиля | 5 мин |
| Расширение × 3 | 5 мин |
| Настройки × 3 | 10–15 мин |
| Хаб | 3 мин |
| Prepare × 3 | 3 мин |
| Быстрая проверка | 5–10 мин |

## 4. Живые тесты (один раз, 1,5–2 ч)

Делать на одном сервере, по `README.md` архива. Главные:

| Тест | Что даёт | Время |
|---|---|---|
| T1 | весь путь до оплаты на 18 Pro | 10 мин |
| T10 (Apple Pay) | откроется ли код Apple Pay от нажатия расширения или нужен клик человека; **не подтверждать** | 15 мин |
| T11 (карта) | заполняются ли карта и адрес плательщика; **не платить** | 15 мин |
| T12 (Place Order самим) | что показывает банк; **настоящая покупка, в банке отклонить** | 15 мин |
| T6 (3 профиля + хаб) | один победитель, двое в запасе, корзины чистятся | 20 мин |
| сухой прогон на моке | всё целиком без Apple, включая «закрытый магазин» | 15 мин |

Если серверы на Windows — T10 обязательно повторить на Windows: показ кода Apple Pay в Chrome на Windows мы не проверяли.

## 5. Обновление на новую версию (~5 мин на сервер)

1. Заменить содержимое папки `apple-drop-test-setup` файлами из нового архива (папку не переименовывать).
2. В каждом профиле: `chrome://extensions` → у «Apple Drop Assistant» кнопка обновления (круговая стрелка).
3. Настройки сохраняются. Если расширение удалить и поставить заново — настройки пропадут, поэтому перед этим «Экспорт JSON» (и удалить файл после повторного импорта — в нём карта).

## 7. Что расширение делает само

- Ждёт старта, следит за открытием через данные сайта, не перегружая его рефрешами.
- Переживает закрытый магазин, пустую страницу, «We'll be back», редиректы, заглушки «Almost there», страницу очереди.
- Выбирает United Arab Emirates в баннере страны.
- No trade-in, No AppleCare, Add to Bag, не уходит со страницы до подтверждения.
- Проверяет корзину: одна позиция нужной модели, количество 1; при пустой корзине повторяет.
- Check Out, Continue as Guest.
- Самовывоз: город, магазины по очереди, дата, окна (сначала желаемые), при занятом окне — следующее.
- Контакты получателя.
- Способ оплаты; карта и адрес плательщика; ждёт медленный блок карты до 10 с, иначе переключает на Apple Pay.
- Очередь оплаты: вперёд выходит одно окно за раз, со звуком.
- Review, галочка условий; Apple Pay — нажатие кнопки; карта — Place Order (если включено), один раз.
- Повторы при «unexpected error», «try again».
- Номер заказа, запись о заказе, уведомление.
- Несколько профилей: один ведёт заказ, остальные в запасе и чистят корзины; при падении главного заказ переходит запасному.

## 9. Что контролировать на дропе

Расширение зовёт человека звуком, уведомлением, выводом окна вперёд и крупным баннером внизу страницы. Состояние каждой вкладки видно на плашке в углу и в popup; на дашборде хаба — все профили сервера.

| Ситуация | Как узнаешь | Что делать | Насколько вероятно (по опыту 18 Pro) |
|---|---|---|---|
| Магазин закрыт до/после старта | «Apple Store закрыт», вкладки `CLOSED` | ничего | высокая |
| Очередь Apple | `QUEUE` | ничего, страницу не трогать | средняя |
| Заглушка нагрузки | `BUSY` | ничего | высокая |
| Apple отклоняет Add to Bag несколько раз | звук, подсветка Add to Bag, `ASSIST` | нажать кнопку самому | средняя |
| Баннер выбора страны 3 раза | «выбор страны… проверь VPN», `STUCK` | проверить VPN/интернет сервера | низкая без VPN |
| Корзина пуста 3 раза подряд | «корзина пуста 3×», `STUCK` | Clean bag → Start, или пусть ведёт запасной профиль | средняя |
| «Unexpected error» на чекауте | в логе «повтор» | ничего; если повторы кончились — `NEED_HUMAN` | высокая |
| Окно самовывоза заняли | в логе «следующее окно» | ничего | высокая |
| Нет самовывоза ни в одном магазине | уведомление «нет самовывоза», `STUCK` | решить: ждать, другой магазин, доставка | средняя после первых минут |
| Поле не принято | `NEED_HUMAN` | поправить, Continue | низкая |
| Блок карты не загрузился | «переключаюсь на Apple Pay» | плательщик сканирует код Apple Pay | средняя |
| Код Apple Pay не открылся от нажатия расширения | подсвечена кнопка Apple Pay | нажать её | **высокая** (так устроен Chrome) |
| Подтверждение банка | push в приложении банка у владельца карты | подтвердить | всегда при карте |
| Ошибка после Place Order | баннер «после Place Order: …» | не повторять, проверить почту | средняя (12.09 были дубли) |
| Оплату не подтвердили 10 мин | `PAY_TIMEOUT`, уведомление | найти, кто не подтвердил | низкая |
| Вкладка или Chrome закрылись, сервер уснул, удалённая сессия отвалилась | вкладки пропали, на дашборде профиль «○» | восстановить, Start; при хабе заказ уже перешёл запасному | низкая при подготовке |
| Профиль без хаба гонится за тем же заказом, что и другой | два окна на оплате с одним получателем | оплатить одно, второе закрыть | только при ошибке настройки |

## 10. Сколько людей нужно на 4 сервера

### Роли

| Роль | Что делает | Где должен быть |
|---|---|---|
| **Оператор** | готовит серверы, жмёт Start, смотрит на экраны, жмёт подсвеченные кнопки, правит поля, решает STUCK | перед экранами своих серверов (физически или через удалённый рабочий стол со звуком) |
| **Плательщик** | подтверждает оплату на своём телефоне | Apple Pay — должен **видеть экран** сервера, чтобы отсканировать код; карта — где угодно, банк пришлёт push |
| **Координатор** (по желанию) | следит за почтой получателей, ловит дубли, решает спорные случаи, ведёт таблицу | где угодно, на связи с операторами |

Один человек может совмещать оператора и плательщика, если оплата идёт с его телефона.

### Что определяет нагрузку

1. **Сколько заказов на сервер.** Каждый заказ — 20–60 с внимания при оплате. Заказы приходят на оплату волной в первые минуты после старта.
2. **Сколько экранов может смотреть один человек.** Звук и уведомления каждого сервера слышны только у его экрана. Реально следить за 2 серверами одновременно; 4 — только если все на одном столе и заказов мало.
3. **Способ оплаты.** Apple Pay привязывает плательщика к экрану (сканировать код). Карта с «Place Order самим» отвязывает: оператору не нужно ничего жать, владелец карты подтверждает push у себя.
4. **Скорость.** В ОАЭ квоты 18 Pro ушли меньше чем за 20 минут, окна в популярных магазинах — быстрее. Каждая минута ожидания оплаты — риск, что окно или товар уйдут. Пока заказ не оплачен, он не оформлен.

### Рекомендации

| Схема на 4 сервера | Заказов всего | Операторов | Плательщиков | Комментарий |
|---|---|---|---|---|
| по 1 заказу на сервер (3 профиля гонятся за ним, хаб) | 4 | **2** (по 2 сервера) | 1–4 | один человек справится, только если все 4 экрана перед ним и все 4 оплаты с его телефона; запаса на сбои почти нет |
| по 2 заказа на сервер | 8 | **2–3** | 2–8 | с картой и «Place Order самим» хватит 2 операторов; с Apple Pay — 3 |
| по 3 заказа на сервер (каждый профиль свой заказ) | 12 | **4** (по одному на сервер) | до 12 | волна из 3 оплат на каждом сервере одновременно |
| по 4 заказа на сервер | 16 | **4 + координатор** | до 16 | на пределе: 4 профиля на сервер, 12 вкладок |

Как считать самому: на одного оператора — не больше 2 серверов и не больше ~4 оплат в первой волне. Плательщиков столько, сколько разных карт / Apple Pay; при Apple Pay каждый плательщик должен видеть экран своего сервера в момент оплаты.

### Трудозатраты по людям

| Этап | 1 человек | 4 человека |
|---|---|---|
| Данные и JSON (12 профилей) | 1–1,5 ч | 1–1,5 ч (лучше один, чтобы не ошибиться) |

## 11. Что расширение не закрывает (проверить до 16.10)

| Риск | Что делать |
|---|---|
| Серверы в дата-центре или вне ОАЭ: Apple может показывать выбор страны, очередь или отказывать чаще | лучше машины в ОАЭ с обычным интернетом; проверить T1 и Prepare на каждом сервере |
| Удалённый рабочий стол свёрнут или отключён — Chrome тормозит окно | держать сессию подключённой и окно развёрнутым; на Windows не блокировать экран |
| Код Apple Pay от нажатия расширения не открывается | закладывать 1 клик человека на каждый заказ с Apple Pay (T10) |
| Apple Pay в Chrome на Windows | проверить T10 на Windows до дропа |
| Подтверждение банка (3-D Secure): как выглядит и сколько ждёт | T12 до дропа; плательщикам держать телефоны с приложением банка под рукой с 16:00 |
| Часы сервера отстают | проверить на time.is накануне и в день дропа |
| Один заказ запущен на двух серверах | следить по таблице распределения: заказ — только на одном сервере |
| Ошибка после Place Order | не повторять, сначала почта и номер заказа |

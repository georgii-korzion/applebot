# 40–50 аккаунтов на 4 серверах и 3 локальных компьютерах: сколько времени, людей и что ещё доделать

Расчёт под схему FLEET-SPEC (`docs/FLEET-RUNBOOK.md`): один хаб в интернете, один `fleet.json` на всех, на каждой
машине клоны одного шаблона Chrome, запуск скриптом. Старый расчёт по схеме «хаб на каждой машине, JSON руками в
каждый профиль» — `docs/PLAN-50.md`; сравнение с ним в §6. Времена — оценки по мок-прогонам и по тому, сколько шагов
осталось руками; живой сайт Apple под нагрузкой 16.10 заранее не известен (§8).

---

## 0. Коротко

**Один человек: 12–16 часов чистой работы до 16.10**, то есть два с половиной рабочих дня, из них ~3,5 часа — таблица
аккаунтов, которую можно отдать помощнику (тогда 9–12 часов своих). Календарно укладывается в вечер 12.10 + 13, 14 и
полдня 15.10 (§3).

| Блок | Время (один человек) | Можно отдать |
|---|---|---|
| Хаб в интернете (Railway или VPS + Caddy) | 30–45 мин | — |
| Таблица аккаунтов → `fleet.json` (47 строк) + сверка | 3–4 ч | да, таблицу — помощнику |
| Прокси: купить 12–16 IP ОАЭ, проверить каждый | 30–45 мин | — |
| Сервер 1 с нуля + F1 (первый клон живьём) | 50–60 мин | — |
| Серверы 2–4 (из образа сервера 1 — 45–60 мин; каждый с нуля — 1,5 ч) | 1–1,5 ч | да, по RDP-инструкции |
| 3 локальных компьютера | 1–1,5 ч | да, владельцу компьютера |
| Живые проверки F2–F8 на одном сервере (§4) | 3–3,5 ч | — |
| 15.10: Prepare все, IP у всех, карты, стратегии | 1–1,5 ч | — |
| **Итого до дропа** | **12–16 ч** | |
| День дропа 15:00–17:00 | 8 человек × 2 ч (§5) | |

Что нужно купить или решить, кроме времени:

1. **4 сервера** Windows Server 2019/2022, 8 vCPU / 16 ГБ / **60–80 ГБ** диска (32 ГБ не хватит: ОС 20 ГБ + файл
   подкачки + Chrome + 8 профилей), выделенные ядра. Регион не важен — в Apple профили ходят через прокси.
2. **12–16 прокси ОАЭ** (сейчас есть один): правило до проверки F2 — не больше 3 профилей на один IP. Серверы стоят не в
   ОАЭ, значит на них через прокси идут **все** профили: 32 профиля / 3 = 11–12 IP. Локальные компьютеры в ОАЭ могут
   держать 3 профиля напрямую, остальные — через прокси: ещё 3–4 IP.
3. **Где хаб**: Railway (быстрее всего, домен даёт сам) или любой Linux VPS + Caddy и поддомен (например `hub.korzion.ae`).
4. **8 человек на 16.10**: по оператору на сервер и локальный компьютер + координатор; плательщики — владельцы карт на
   телефоне (§5). Минимум 5, если почти все заказы — карта с `autoPlaceOrder`.

## 1. Раскладка

| Машина | Префикс | Профилей | Откуда IP в Apple | Прокси |
|---|---|---|---|---|
| Сервер 1 | `s1` | 8 | только прокси (сервер не в ОАЭ) | 3 (3 + 3 + 2) |
| Сервер 2 | `s2` | 8 | прокси | 3 |
| Сервер 3 | `s3` | 8 | прокси | 3 |
| Сервер 4 | `s4` | 8 | прокси | 3 |
| Локальный 1 | `l1` | 5–6 | 3 напрямую (домашний IP ОАЭ) + прокси | 1 |
| Локальный 2 | `l2` | 5–6 | то же | 1 |
| Локальный 3 | `l3` | 5–6 | то же | 1 |
| **Итого** | | **47–50** | | **15** |

Имена профилей — `s1-p01 … s1-p08`, `l1-p01 …`; они же — имена папок клонов и ключи в `fleet.json`. Один профиль —
один заказ — один Chrome; очереди оплаты между профилями нет, каждый выходит к оплате сам (в отличие от старой схемы).

Почему 8 на сервер: 8 vCPU / 16 ГБ держат 8 окон Chrome с запасом (≈1 ГБ на профиль в пике чекаута + 3 ГБ Windows);
`refresh` у 8 окон — до 5 загрузок страницы в секунду с одного сервера, это нагрузка на процессор, не на память. Смесь
половина `hold` / половина `refresh` снимает половину этой нагрузки. Больше 10 на сервер — только после замера на F2.

Допущения: локальные компьютеры стоят в ОАЭ на домашнем/офисном интернете (иначе им тоже нужны прокси на все
профили); серверы — в дата-центре вне ОАЭ (Timeweb и т. п.). Если серверы будут в ОАЭ — прокси на них нужны только
сверх 3 профилей на IP (проверка F5).

## 2. Время по шагам

Все шаги — по `docs/FLEET-RUNBOOK.md`; здесь только сколько они занимают и что отдать другим.

### 2.1 Хаб — 30–45 минут, один раз

| Шаг | Время |
|---|---|
| Railway: сервис из репозитория, `HUB_TOKEN`, `HUB_DASH_TOKEN`, том для `/srv/drop` или `FLEET_JSON`, домен | 20–30 мин |
| или VPS + Caddy: `hub/README.md`, A-запись поддомена, systemd | 40–50 мин |
| Проверка: `/healthz`, дашборд «профилей 0/0» | 5 мин |

### 2.2 Таблица аккаунтов → `fleet.json` — 3–4 часа, можно отдать

Таблица в Google Sheets по колонкам `fleet.example.csv` (профиль/сервер, стратегия, оплата, имя, фамилия, email,
телефон, карта, срок, CVV, имя на карте, адрес плательщика, прокси, магазины, город). Экспорт CSV →
`node hub/fleet-from-csv.mjs accounts.csv --out fleet.json` → `node hub/check.mjs fleet.json`.

| Шаг | На аккаунт | На 47 |
|---|---|---|
| Собрать данные получателя и способ оплаты (переписка с людьми — основное время) | 3–4 мин | 2,5–3 ч |
| Сверка вторым человеком: ФИО как в документе, телефон `05XXXXXXXX`, карта проходит проверку | ~1 мин | 45–60 мин |
| CSV → `fleet.json`, `check.mjs`, исправить ошибки, положить на хаб | | 10–15 мин |

Карты нужны только профилям с `payment: manual`. Для Apple Pay — только контакт; карта в Wallet телефона, который
сканирует QR. Прокси в таблице — колонка `proxy` вида `http://user:pass@host:port`, по 3 строки на один прокси.

### 2.3 Прокси — 30–45 минут

Купить 12–16 IP ОАЭ у того же провайдера, что и рабочий; проверить каждый: `curl -x http://user:pass@host:port
https://ipinfo.io/json` → `"country": "AE"`. Записать в таблицу. Проверка «изнутри» (расширение, страница Apple без 403)
— на F2.

### 2.4 Сервер 1 — 50–60 минут с нуля, включая F1

| Шаг | Время |
|---|---|
| Создать VM (Windows Server, 8 vCPU / 16 ГБ / 60–80 ГБ), дождаться, RDP | 10 мин |
| Скопировать на сервер `apple-drop-test-setup.zip` (внутри `ext.zip`, `fleet/fleet.ps1`) в `C:\drop` | 5 мин |
| `Set-ExecutionPolicy RemoteSigned`; `.\fleet.ps1 bootstrap -Zip C:\drop\ext.zip` (часовой пояс, время, не спать, Chrome, автообновление выкл., расширение) | 10–15 мин (Chrome качается ~2 мин) |
| `init -Prefix s1 -Hub …` → в Chrome Load unpacked `C:\drop\ext` → закрыть → `check-template` | 10 мин |
| `clone -Count 8` | 2 мин |
| **F1**: `start -Only p01`, popup «s1-p01 · конфиг v1 · хаб ●», строка на дашборде | 10–15 мин |

### 2.5 Серверы 2–4 — 45–60 минут все вместе (из образа) или 1,5 часа (каждый с нуля)

Главная оптимизация раскатки: после F1 на сервере 1 **снять образ (snapshot/image) виртуалки** и создать серверы 2–4
из него. На каждом остаётся: RDP → `.\fleet.ps1 init -Prefix s2 -Hub …` (перепишет `fleet.local.json`; откроется
Chrome с шаблоном — просто закрыть) → `check-template` → `clone -Count 8` → `start -Only p01` → строка `s2-p01` на
дашборде. 10–15 минут на сервер.

Если образов у хостера нет: повторить §2.4 без создания образа — 25–35 минут на сервер (Chrome уже в архиве, bootstrap
делает остальное). Это можно отдать второму человеку по RDP: инструкция — §3 рунбука, одна команда за другой.

Шаблон `tpl` в образе чистый (расширение есть, cookies apple.com нет — `check-template` это проверяет), так что
клоны на разных серверах не наследуют одну сессию Apple.

### 2.6 Локальные компьютеры — 20–30 минут каждый

Mac: `fleet.sh init/check-template/clone/start` (`fleet/fleet.sh`, корень `~/drop`). Windows: `fleet.ps1` как на сервере,
`bootstrap` можно пропустить (руками: часовой пояс Dubai, не спать, автообновление Chrome не трогать до 17.10). Chrome
обычно уже стоит. 5–6 клонов. Отдать владельцу компьютера с рунбуком §3 — реально: команд пять.

### 2.7 Живые проверки F2–F8 — 3–3,5 часа, один раз, на сервере 1 (13–14.10)

| Проверка | Время | Что решает |
|---|---|---|
| F2: 5–8 клонов через **один** прокси до Review, без оплаты | 45 мин | сколько профилей можно на один IP (3 → 8 = в 2,5 раза меньше прокси), память/CPU сервера под 8 окон |
| F3: Apple Pay на Windows (debugger-клик → лист с QR) | 30 мин | работает ли Apple Pay через RDP; иначе `applePayClick: "dom"` и жмёт человек |
| F4: один **настоящий** заказ картой через прокси, потом отменить | 45 мин | антифрод Apple/банка на IP прокси; как выглядит push банка |
| F5 (вместо «сервер в ОАЭ»): один профиль с сервера **без** прокси | 15 мин | что Apple показывает с IP дата-центра вне ОАЭ (ожидание: работает, но боевые — только через прокси) |
| F6: Start/Stop/Разослать конфиг/CSV с дашборда на 10 профилей двух серверов | 30 мин | команды хаба живьём |
| F7: выключить хаб посреди прогона | 15 мин | автономность (на моке проверено, живьём — для спокойствия) |
| F8: окно за отключённой RDP-сессией 10 минут | 20 мин | душит ли Windows таймеры; иначе RDP не разрывать или `tscon` в консоль |

После каждой — **Clean bag** в popup профиля (или `reset -Only pNN`).

### 2.8 15.10 — 1–1,5 часа

«Проверить IP у всех» → у всех `AE` (или IP сервера у прямых локальных); «Prepare все» → у всех Prepare ✓; карты:
`check.mjs` без ошибок, `cfg v` у всех одинаковая; стратегии по плану (половина `hold`); у Apple Pay-профилей —
телефон с картой в Wallet рядом с той машиной. Красные строки — по §8 рунбока. После 12:00 15.10 расширение
не обновлять.

## 5. День дропа: люди

| Роль | Сколько | Где | Что делает |
|---|---|---|---|
| Оператор сервера | 4 (по одному) | RDP-окно сервера, звук включён | 15:00 `fleet.ps1 start`, смотрит дашборд и окна; жмёт подсвеченную кнопку Apple Pay / Place Order, если расширение зовёт; капча |
| Оператор локального компьютера | 3 (владельцы) | у экрана | то же; у него же iPhone для QR Apple Pay своих профилей |
| Координатор | 1 | дашборд + чат | кто OPEN, кто Billing, кто ORDERED; дубли после Place Order; связь с плательщиками |
| Плательщик (карта) | владельцы карт | где угодно, телефон в руке с 15:55 | подтверждает push банка |
| Плательщик (Apple Pay) | у экрана той машины | рядом с оператором | сканирует QR с экрана, Face ID |

**Способ оплаты — главный выбор для серверов.** Apple Pay = QR на экране, сканировать надо с той машины: 8 профилей
сервера → 8 сканирований подряд по 30–40 с = 4–5 минут, последние заказы рискуют. Для серверов разумнее **карта +
`autoPlaceOrder: true`**: расширение само доходит до Place Order, человек нужен только для push банка у себя в
телефоне, 8 заказов сервера уходят параллельно за 30–60 с. Apple Pay — там, где владелец iPhone сидит у экрана
(локальные компьютеры). При карте без `autoPlaceOrder` оператор жмёт Place Order в 8 окнах сам — ~1 минута на все.

| Время | Операторы | Координатор |
|---|---|---|
| 15:00 | `start` (или `status`, если окна с 15.10 открыты); popup без красного | дашборд: онлайн 47/47, `cfg v` одна, OPEN пусто |
| 15:30 | ничего не трогать | перекличка плательщиков |
| 16:00–16:10 | смотреть на подсветку и уведомления; QR / Place Order, если нужно | OPEN/Billing/ORDERED по строкам; кто завис — STUCK в логе строки |
| 16:10–16:30 | hold → refresh сам через 5 мин; капча/403 → Stop, другой прокси, Start в строке | дубли: ошибка после Place Order — проверить почту до повтора |
| 16:30+ | не закрывать окна с ORDERED | CSV, стереть карты (`version` +1, Разослать), Stop все |

Минимум людей: 5 (два оператора на четыре сервера при карте с `autoPlaceOrder`, три владельца локальных
компьютеров совмещают, координатор = один из них). Но на сервере с 8 окнами за первые 10 минут ожидаются 8 выходов к
оплате и 1–3 вмешательства — по оператору на сервер спокойнее.

## 8. Риски, которые ломают расчёт

| Риск | Чем проверяется | Если сработал |
|---|---|---|
| Apple режет IP прокси (403/капча) или дата-центровые IP вообще | F2 (13.10) | другие прокси (резидентные), меньше профилей на IP → больше IP |
| Apple Pay через RDP на Windows не открывает лист | F3 | `applePayClick: "dom"`, человек жмёт; или карта |
| Банк/Apple отклоняет оплату с IP прокси | F4 | карты только у профилей на домашнем IP ОАЭ (локальные); серверы — Apple Pay |
| Отключённая RDP-сессия душит Chrome | F8 | не разрывать RDP (сворачивать окно), `tscon`, доработка №2 |
| Диск 32 ГБ забился | при заказе сервера | 60–80 ГБ сразу |

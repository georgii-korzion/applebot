# Флот на дроп 16.10 — пошагово для владельца

Что получается: N профилей Chrome на нескольких серверах, каждый — отдельная сессия Apple со своим заказом,
своим прокси (или без) и своей стратегией ожидания. Все берут конфиг с одного хаба и видны на одном дашборде.
Профили **автономны**: хаб только раздаёт конфиг и показывает состояние; упал хаб — дроп идёт дальше.

Коротко по датам:

| Когда | Что |
|---|---|
| сейчас → 12.10 | хаб в интернете (§1), `fleet.json` (§2), сервер + шаблон + клоны (§3), проверки F1–F8 (§6) |
| 13–14.10 | заполнить `fleet.json` боевыми контактами/картами/прокси, `node hub/check.mjs`, разослать |
| 15.10 | Prepare все с дашборда (§4), проверить IP у всех, карты и Apple Pay в каждом профиле |
| 16.10, 15:00 | запустить профили (`fleet.ps1 start`), смотреть дашборд (§5) |
| 16.10, 16:00 | дроп: расширение само; человек — QR Apple Pay / Place Order / банк |
| после | CSV, стереть карты, Stop все (§7) |

Ограничения, которые нельзя обойти (HANDOFF §2): никакого подбора/подмены отпечатка браузера, капчу решает
человек, запросы к Apple делает только сама страница, Place Order и подтверждение Apple Pay — только человек.
Единственное исключение — один настоящий клик по кнопке Apple Pay через `chrome.debugger` (FLEET-SPEC §8).

---

## 1. Хаб в интернете (один раз, ~20 минут)

По `hub/README.md`: VPS с Caddy (рекомендуется) или Railway. На выходе нужны три строки:

```
дашборд:  https://hub.example.com/?token=<HUB_DASH_TOKEN>
профили:  wss://hub.example.com/ws?token=<HUB_TOKEN>
fleet:    /srv/drop/fleet.json   (на хабе)
```

Проверка: `curl -s https://hub.example.com/healthz` → `{"ok":true,…}`; дашборд открывается, «профилей 0/0».

## 2. `fleet.json` — все профили в одном файле

Образец — `fleet.example.json` в корне репозитория. Структура: верх (`openAt`, `baseUrl`, `timing`), `defaults`
(общее для всех заказов: цели, магазины, оплата, стратегия, прокси, …) и `profiles` — по профилю то, что
отличается. Имя профиля = `<сервер>-p<NN>`, например `nl1-p03` (сервер `nl1`, третий клон). Один профиль = один
заказ (`racersPerProfile` 1).

Что решить по каждому профилю:

- **Контакт** (`contact`: имя, фамилия, email, телефон `05XXXXXXXX`) — обязателен, иначе хаб вернёт 422 и профиль не
  стартует.
- **Оплата**: `"payment": "applepay"` (лист с QR, сканирует человек телефоном) или `"manual"` + `card` + `billing`
  (расширение заполняет карту, человек жмёт Place Order и подтверждает в банке). `cardFallback: null` — на Apple Pay
  само не переключится.
- **Стратегия** (FLEET-SPEC §4): `refresh` — перезагружает страницу по фазам (3 с за минуту до, 1,5 с после);
  `hold` — не перезагружает, ждёт своего OPEN по JSON, через `holdFallbackSec` (300 с) переходит на refresh.
  Разумная смесь: половина `hold`, половина `refresh` — неизвестно, кого Apple пускает первым.
- **Прокси** (`proxy`: `{scheme, host, port, username, password}` или `null`) — ставит расширение, не Chrome.
  Правило до проверки F2/F5: **не больше 3 профилей на один IP** (и прокси, и сервер без прокси).
- `autoStart: true` (по умолчанию) — профиль взводится сам при запуске окна, Start нажимать не надо.

Проверить файл: `node hub/check.mjs fleet.json` (печатает каждого, ошибки, предупреждения про IP). Положить на хаб
(`/srv/drop/fleet.json`) — хаб перечитает сам в течение 2 с. Любая правка потом: увеличить `version`, сохранить,
на дашборде «Разослать конфиг» (профили не в гонке возьмут сразу, в гонке — при следующем Start).

**Карты и пароли прокси лежат в этом файле открытым текстом** — только на хабе и у владельца, в git не класть.

## 3. Сервер: Chrome, шаблон, клоны (на каждом сервере, ~15 минут)

Нужно: Windows Server/10/11 с RDP (или Mac), 8+ ГБ ОЗУ на 10 профилей, обычный Google Chrome.

1. **Система**: часовой пояс Asia/Dubai (`Set-TimeZone 'Arabian Standard Time'`), язык English, спящий режим и
   блокировка экрана выключены, **RDP-сессию не отключать** (Chrome в отключённой сессии считает окна скрытыми и
   душит таймеры; флаги запуска это смягчают — F8). Автообновление Chrome выключить (службы `gupdate`/`gupdatem`
   остановить) или просто не перезапускать Chrome 15–16.10.
2. **Расширение**: собрать `npm run pack` → `dist.zip`; на сервере распаковать в `C:\drop\ext` (должен быть
   `C:\drop\ext\manifest.json`). Скрипт флота: скопировать `fleet\fleet.ps1` в `C:\drop\`.
   PowerShell: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` один раз.
3. **Шаблон**:
   ```
   cd C:\drop
   .\fleet.ps1 init -Prefix nl1 -Hub "wss://hub.example.com/ws?token=<HUB_TOKEN>"
   ```
   Откроется Chrome с профилем-шаблоном на `chrome://extensions`: включить Developer mode → Load unpacked →
   `C:\drop\ext`. Убедиться, что расширение включено. **На apple.com не заходить, настройки расширения не
   трогать** (иначе все клоны унаследуют одну сессию/одно имя). Закрыть Chrome полностью.
   ```
   .\fleet.ps1 check-template
   ```
   Должно быть: расширение в настройках есть, cookies без apple.com, «Шаблон готов».
4. **Клоны**: `.\fleet.ps1 clone -Count 10` → `C:\drop\p01…p10` = профили `nl1-p01…nl1-p10`. Имена должны быть в
   `fleet.json`.
5. **F1 — первый клон**: `.\fleet.ps1 start -Only p01`. В окне: `chrome://extensions` — расширение включено, без
   «повреждено»; значок расширения → popup: профиль `nl1-p01`, «конфиг v1 · хаб ●», стратегия. На дашборде
   строка `nl1-p01` онлайн. Если Chrome отверг копию профиля (расширение исчезло) — запасной путь: в каждом клоне
   Load unpacked руками один раз, остальное в скрипте то же.
6. Остальные команды: `start` (все, плиткой по мониторам, 1,5 с между окнами), `start -Only p03,p07`, `stop`,
   `status`, `reset -Only p03` (сломанную сессию заменить свежей копией шаблона), `template` (открыть шаблон ещё
   раз, например обновить расширение — потом `reset` клонов).

Mac вместо Windows: `fleet/fleet.sh` с теми же командами (`--prefix`, `--hub`, `--count`, `--only`), корень `~/drop`.

Что делает клон при запуске (FLEET-SPEC §5.4): адрес окна `…/buy-iphone/iphone-18-pro#drop=nl1-p03&hub=wss://…` →
расширение запоминает имя и хаб, снимает хеш из адреса, берёт конфиг с хаба, ставит прокси, проверяет выходной IP
и при `autoStart` взводит гонку в этой же вкладке. Перезапуск Chrome **после оформленного заказа** или после
ручного Stop гонку заново не начинает (только Start руками или с дашборда).

## 4. 15.10 — прогрев и проверка

На дашборде:

1. Все профили онлайн (`онлайн N/N`), у каждого `cfg v` = текущая версия, без красного.
2. **«Проверить IP у всех»** — в колонке IP·страна у профилей с прокси IP прокси и `AE`; без прокси — IP сервера.
   Красное «IP не удалась» = прокси не отвечает: проверить логин/пароль/порт в `fleet.json`.
3. **«Prepare все»** — в каждом профиле открывается вкладка прогрева: главная apple.com/ae (гео-cookie), корзина
   (пуста?), страница цели (конфигурация доступна). В popup профиля строка «Prepare ✓ … — что проверено». Красное
   — читать деталь (капча/403 на этом IP → менять прокси, §13.1 спеки).
4. Оплата: у профилей с картой расширение заполнит её на дропе само; у Apple Pay — убедиться, что на телефоне,
   которым будут сканировать QR, карта в Wallet.
5. Стратегии: в таблице видно `hold`/`refresh`; переключить одного — кнопка в строке, всех — «все → hold/refresh».

После Prepare окна можно оставить открытыми до дропа (сессия Apple уже есть) или `fleet.ps1 stop` и запустить
снова 16.10 — конфиг и имя сохраняются в профиле.

## 5. 16.10 — день дропа

**15:00** (за час): на каждом сервере `.\fleet.ps1 start` (или `status` — если окна с 15.10 ещё открыты, не
трогать). Дашборд: все онлайн, у всех состояние ARMED/HOLD, `OPEN` пусто, отсчёт до `openAt`. Prepare повторять
не нужно.

**15:59–16:00**: расширение само. На дашборде:

- колонка OPEN +с — кого Apple пустила и когда (первый OPEN — в шапке);
- Billing +с — дошёл до оплаты (цель: ≤ 15 с от своего OPEN);
- `hold` без OPEN 5 минут сам перейдёт на `refresh` (строка в логе «hold не дождался…»).

**Что делает человек** (только это):

- **Apple Pay**: окно профиля само выходит вперёд, расширение жмёт кнопку Apple Pay (программно → настоящий клик
  через debugger → подсветка кнопки, если не вышло). Открылся лист с QR → сканировать iPhone, подтвердить. Лист
  закрылся без заказа — расширение повторит до 3 раз, потом подсветит кнопку: жать самому.
- **Карта**: расширение заполнило карту и открыло Review → человек проверяет и жмёт **Place Order**, подтверждает в
  приложении банка. Ошибка после Place Order → **не жать второй раз** (12.09 были дубли): проверить почту/номер.
- **Капча / 403 / «something went wrong»** — расширение останавливается и уведомляет; обхода нет, можно
  попробовать Stop → Start на другом прокси (поменять в `fleet.json`, Разослать, Start в строке).
- Номер заказа `W…` появился → строка зелёная, ORDERED, вкладка больше ничего не делает и страницу не меняет —
  **не закрывать окно**, пока не прочитали подтверждение.

Дашборд можно не держать: он только показывает. Хаб упал — профили продолжают; поднялся — всё доехало (повтор
OPEN/PAY_READY/ORDERED после переподключения).

## 6. Живые проверки до дропа (F1–F8, на iPhone 18 Pro `MJR54AH/A`, без оплаты или с одной настоящей)

Эти проверки на моке сделать нельзя — только живой сайт. Что смотреть и что считать результатом:

| № | Что сделать | Хорошо, если | Если нет |
|---|---|---|---|
| F1 | §3 п. 5 на первом Windows-сервере | расширение в клоне включено, popup показывает имя и `конфиг v1 · хаб ●` | Load unpacked руками в каждом клоне (§13.6 спеки) |
| F2 | 5 клонов на одном сервере **без прокси**, Start с дашборда, цель до Review (`autoPlaceOrder` выкл., Apple Pay не подтверждать) | все 5 до Billing/Review, в логе нет 403/капчи/редиректа на `/nl` | уменьшить до ≤3 на IP или всем прокси; проверить F5 |
| F3 | Apple Pay на Windows: один профиль до Review | лог «лист Apple Pay открыт (debugger-клик…)», QR на экране, после закрытия листа сайт ведёт себя как обычно, строки «debugger не отключ…» нет | `applePayClick: "dom"` в `fleet.json` (без debugger, человек жмёт сам) |
| F4 | профиль через прокси ОАЭ до Review + **одна настоящая оплата картой** с сервера в NL (потом отменить заказ) | заказ прошёл, банк подтвердил | антифрод на чужой IP: карты ставить только профилям на серверах/прокси «своей» страны карты |
| F5 | сервер в ОАЭ без прокси до Review | нет 403/капчи | прокси нужен и там |
| F6 | хаб в интернете, 10 профилей с двух серверов: Start все / Stop все / Разослать конфиг (поменять `version`), CSV | все команды дошли (лог профиля «команда хаба: …»), `cfg v` обновилась у не-гонящихся, CSV со всеми | смотреть `journalctl -u drop-hub`, токен/Origin |
| F7 | выключить хаб (`systemctl stop drop-hub`) посреди прогона до Review | профили не меняют поведения, popup «hub ○»; включили — строки на дашборде восстановились | — (это и есть автономность; на моке проверено e2e `hub-down`) |
| F8 | окно за **отключённой** RDP-сессией 10 минут до старта (`armed`) | в логе наблюдателя строки опроса JSON идут раз в ~1,2 с, без провалов | не отключать сессию (сворачивать окно RDP, не разрывать), либо `tscon` в консоль |

После каждой проверки с товаром в корзине — **Clean bag** в popup профиля (или команда `cleanBag` через API).
`fleet.ps1 reset -Only pNN` возвращает профиль к шаблону (новая сессия Apple), если сессия «испорчена».

Что проверено на моке и повторять живьём не нужно: стратегии hold/refresh по таблице §4.2, фолбэк hold→refresh,
identity из адреса, обновление конфига (в гонке — pending), прокси с логином и проверка IP, повторы Apple Pay при
закрытии листа, поля карты через 45 с, профили не мешают друг другу, после ORDERED нет навигаций, 6 клонов до
Billing ≤ 15 с от своего OPEN.

## 7. После дропа

1. Дашборд → **Скачать CSV** (все заказы всех профилей: номер, товар, магазин, окно, контакт, время OPEN/Billing/заказа).
   Дубль — в popup каждого профиля «Экспорт».
2. **Стереть карты**: в `fleet.json` у всех `card` → пустые строки, `version` +1, сохранить → «Разослать конфиг».
   Профили в гонке возьмут конфиг после Stop (следующий пункт) — проверить на дашборде `cfg v` у всех новая.
3. **Stop все** на дашборде (вкладки с ORDERED остаются как есть). Затем `.\fleet.ps1 stop` на серверах.
4. Профили с оформленными заказами не трогать до получения товара (там подтверждение и сессия). Остальные —
   Clean bag, при желании `reset`.
5. На хабе: `runtime/records.json` и `runtime/log.ndjson` — архив на память; `fleet.json` без карт можно оставить.

## 8. Если что-то не так

| Симптом | Куда смотреть | Что делать |
|---|---|---|
| Профиль офлайн на дашборде | popup: «hub ○», лог `HUB: отключён` | хаб жив? (`/healthz`); токен в `-Hub` совпадает с `HUB_TOKEN`? `fleet.ps1 init -Hub … ` + `start` |
| popup «профиль не назначен» | клон запущен не через `fleet.ps1 start` (без `#drop=`) | `stop` → `start` скриптом |
| `cfg v` красная / «конфиг с ошибками» | `node hub/check.mjs fleet.json`, лог хаба | исправить профиль в `fleet.json`, `version` +1 |
| IP не ОАЭ при прокси / «IP не удалась» | лог `PROXY`, `IP` | логин/пароль/порт прокси; `scheme` http/socks5; прокси жив? (`curl -x`) |
| Все окна «ждут» после 16:00, OPEN ни у кого | лог наблюдателя, `watch` в статусе | это сайт; `hold` сам перейдёт на refresh через 5 мин; ничего не нажимать |
| Капча / 403 | лог `STUCK`/`NEED_HUMAN`, уведомление | решить капчу руками в окне; 403 — другой IP (прокси), Start в строке |
| Apple Pay лист не открылся | лог «нужен клик человека», кнопка подсвечена | нажать кнопку самому в окне профиля |
| Два окна одного профиля | дашборд: предупреждение «подключился дважды» | закрыть лишнее (`fleet.ps1 stop -Only pNN`, затем `start -Only pNN`) |
| Chrome «профиль повреждён» после clone | F1 | Load unpacked руками в клоне; или `reset -Only pNN` |
